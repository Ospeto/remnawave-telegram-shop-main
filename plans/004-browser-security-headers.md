## Why This Matters

The app serves a Telegram Mini App and a generated redirect page through the Go server behind Caddy. Current responses set CORS and a small amount of cache control, but not browser hardening headers such as CSP, `X-Content-Type-Options`, or referrer policy. There is no confirmed active XSS in the audited code; this plan reduces blast radius if a future dependency, content path, or HTML sink regresses.

## Steps

### Step 1: Add app-level security header middleware

In `internal/api/middleware.go`, add an exported middleware:

```go
func SecurityHeadersMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        setSecurityHeaders(w, r)
        next.ServeHTTP(w, r)
    })
}
```

Implement `setSecurityHeaders` with at least:

- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: no-referrer`
- `X-Frame-Options: DENY` for non-Telegram/browser contexts only if it does not break Mini App embedding. If unsure, omit `X-Frame-Options` and rely on CSP `frame-ancestors`.
- `Content-Security-Policy` tailored by path:
  - For `/redirect`, allow the inline script currently generated by `renderRedirectPage`, for example `script-src 'self' 'unsafe-inline'`; keep all other directives narrow.
  - For the SPA and API, prefer `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; connect-src 'self' https:; object-src 'none'; base-uri 'none'; frame-ancestors 'self' https://web.telegram.org`.

If the Mini App needs a broader `frame-ancestors` policy for Telegram clients, document the exact reason in a code comment and test the resulting header string.

**Verify**: `go test ./internal/api` -> exit 0 or only fails until tests are added in Step 3.

### Step 2: Compose the middleware in the server

In `cmd/app/main.go`, wrap the existing handler:

```go
Handler: api.SecurityHeadersMiddleware(limiter.Middleware(mux)),
```

Keep rate limiting in the chain. Do not remove `corsMiddleware`; it is used during route registration.

**Verify**: `go test ./cmd/app ./internal/api` -> exit 0.

### Step 3: Add header tests

In `internal/api/server_test.go` or a new middleware test file, add tests using a simple `http.HandlerFunc` wrapped in `SecurityHeadersMiddleware`.

Assert:

- `X-Content-Type-Options` is `nosniff`.
- `Referrer-Policy` is `no-referrer`.
- Non-redirect path CSP includes `object-src 'none'`.
- `/redirect` CSP includes the redirect-specific script allowance needed by the current page.

Avoid testing the entire CSP string if a map/set comparison is clearer; the test must still fail if the CSP header is absent.

**Verify**: `go test ./internal/api` -> exit 0.

### Step 4: Build the frontend and inspect CSP compatibility

Run the frontend production build. If it fails, the issue is not CSP because CSP is runtime response metadata; investigate only if the build had already been broken.

If possible in your environment, start the app and manually verify the Mini App HTML and `/redirect` responses include the headers. Do not require live Telegram for this plan.

**Verify**: `cd web-app && npm run build` -> exit 0.
